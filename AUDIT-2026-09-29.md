**New findings, most severe first**

1. **Medium: file-access grants last the whole session and aren't tied to what they were granted for. Reproduced.**

   Like findings 2 and 3, this only matters if the main UI's renderer is compromised (for example by XSS). Every path returned by any open dialog, or by drag and drop, goes into one shared allow-list: [ipc.js:318](src/main/ipc.js#L318) → [file-permissions.js:17](src/main/file-permissions.js#L17). Nothing is ever removed from that list, and every check uses it.
   - **A:** I picked a folder, which is what Preferences → "Change Download location" does. Afterwards, `torrent.create` seeded `seedable/other.txt` from inside that folder with no further prompt (`NEW-A.seedFileInsideChosenFolder: seeded: true`). Choosing a download or watch folder therefore also allows sharing everything in it.
   - **B:** Any single file picked for any purpose can be saved as `externalPlayerPath` ([file-permissions.js:46](src/main/file-permissions.js#L46)), and `openExternalPlayer` then runs it. The harmless `player.sh` ran (`NEW-B.playerRan: "spawned http://127.0.0.1:…"`).
   - The renderer also controls the dialog's options (title, message, button label, default path) through `Object(opts)`, so it can word a dialog misleadingly.

   Fix: keep a separate grant list per purpose (seed sources, download folder, watch folder, external player, subtitles). Have main own the dialog for each purpose, with its own text. Remove grants once they're used or the torrent is gone.

2. **Low: "Remove torrent and data" can trash unrelated files in a folder that already existed. Reproduced at the module boundary.**

   For a torrent with several files, [data-path.js:16-17](src/main/data-path.js#L16) allows trashing the torrent's whole top-level folder. I recorded a torrent with files `Show/ep1.mkv`. Trashing `Show` was allowed, while trashing `Show/unrelated-user-file.txt` directly was rejected. Trashing the folder takes that unrelated file with it. This happens when the download folder already contained a folder with the torrent's name. The files go to the Trash, so they can be recovered. Fix: trash the torrent's own files, then remove folders only if they are empty.

**Out of scope, noted only**

- The app doesn't set `LSFileQuarantineEnabled` in `Info.plist`, and no code applies quarantine. Downloaded files therefore probably get no `com.apple.quarantine` flag, and Gatekeeper wouldn't check a downloaded app or script opened from the list. I found this from the plist and source only; I didn't confirm it with a real download.
- The shipped binary obeys `--test` or `NODE_ENV=test`, which switches it to the `/tmp/WebTorrentTest` profile and the test client. This only affects someone launching it from a command line.

**What is working**

The main renderer is sandboxed with the bridge-only surface, which the suite asserts. Every `handle` channel checks the sender, and every `on` channel is filtered through the `emit` wrapper. The streaming server is loopback-only with per-play tokens that are revoked. Paste and privacy regressions pass on the installed app, with no outbound requests. The dependency audit is clean. Playback, audio, fullscreen, create/seed, subtitles and keyboard playback all pass on the installed build. The build is deterministic: rebuilding gives an identical `app.asar`.

**Not verified**

Real Chromecast/DLNA/AirPlay devices and LAN reachability of the cast proxy; VoiceOver itself (only aria snapshots and Tab order were checked); Windows and Linux runtime on this machine; quarantine with a real download; large or malformed media and multi-GB torrents; the pre-existing risk that the hidden engine window has Node integration.

**Recommended order**

1. Get `20d2de8` onto GitHub so CI runs on it. The push needs a token with the `workflow` scope.
2. Scope grants per purpose (N1).
3. Add `aria-label`s to the torrent row's Play and Remove buttons (#9). Make the symlink error accurate, or skip symlinks (#12).
4. Change removal to delete only the torrent's own files and then empty folders (N2). Bump Electron to 44.4.5.
